# 菜单设计

## 需求与流程

入口位于品牌故事下方。输入店铺名称、经营品类（烧烤、生鲜、盖浇饭等），填写菜品文字或仅上传菜单截图，也支持两者一起提交。点击整理菜单，由云端多模态文本模型提取分类、菜名、价格、单位与规格；整理结果可以编辑，点击生成菜单图后提交已核对菜单与品类，通过现有自动调度生图线路生成竖版菜单图。

默认每次生成一张 2:3 菜单，截图最多 6 张、每张原文件最大 10 MB，PNG/JPEG/WebP。识别输入最长边 2400 像素、JPEG 质量 95%，菜单文字最多 12000 字。无法辨认或冲突的信息标记待确认；生成前必须编辑消除待确认标记。原始资料变更后清空旧整理结果，避免误用旧菜单。

## 实现边界

- `src/components/MenuDesignPage.tsx`：菜单表单、截图上传、可编辑结果、生图结果与下载。
- `src/hooks/useMenuDesignWorkspace.ts`：状态挂载到全局工作区，切换页面保留状态；同步锁阻止重复提交；整理和生图均参与忙碌计数及更新保护。
- `src/lib/menu-design.ts`：输入限制与云端生图请求。截图仅供文字整理，不传入图片生成。
- `src-tauri/src/menu_design.rs`：云端多模态菜单整理；复用品牌故事 OpenAI 兼容文本客户端协议与默认文本线路配置。
- `POST /api/menu-organize`：验证登录，接收文字、品类及图片 data URL，拒绝外部截图 URL；返回 `{menu:string}`。
- `menu.organize`、`menu.image`：提示词只保存在云端模板，客户端无内置提示词兜底。菜单设计需要云端网关。
- `menu_design`：独立历史归档类型，网关 JPEG 质量 95、最长边 4096；下载保留归档尺寸，不套用外卖产品图尺寸。

## 部署依赖

1. 执行 `supabase/migrations/20260918_add_menu_design.sql`，允许菜单图写入生图日志；总量统计仍按所有日志计算。
2. 部署包含 `/api/menu-organize` 的新版网关和 `prompt-templates/generation-prompts.json`。
3. 可选环境变量 `MENU_TEXT_BASE_URL`、`MENU_TEXT_API_KEY`、`MENU_TEXT_MODEL`；未设置则复用品牌故事线路1文本配置，默认模型 `gemini-3.1-flash-lite`。密钥不进入客户端。
4. 客户端界面需要下次安装包更新；纯菜单提示词修改以后只修改服务器模板。

本开发记录不表示生产部署或客户端自动更新已完成。

## 验收

- 支持纯文字、纯截图、文字加截图；空输入禁止整理。
- 不编造缺失价格；冲突或不清楚的内容待确认，人工可改。
- 生图仅包含整理菜单、店名、经营品类及云端提示词，不携带截图。
- 分类在品牌故事与数据分析之间；任务运行中切换页面再返回，输入及任务状态保留。
- 请求失败显示错误，整理内容保留，可重试；成功菜单可预览、下载并归档。
- 验证 TypeScript 构建、菜单行为测试和 Rust 菜单校验/模板测试。付费模型的实际识别与文字生图质量需在部署后用真实菜单验收。
