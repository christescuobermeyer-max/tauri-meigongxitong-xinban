## 已定原则

- 全程先盘点、后备份、再恢复、最后切流，旧服务器在稳定观察期内保持可回滚。
- 不读取或写入文档任何真实密钥、完整签名 URL、数据库连接串和令牌，只记录密钥文件路径与变量名。
- 以服务、端口、域名、目录、持久化数据和外部依赖为迁移边界，不只复制 Git 仓库。
- 旧机先做整盘快照；新机保持 x86_64 架构但使用 Ubuntu 22.04，业务目录用两轮 `rsync` 恢复，机器身份和网络配置使用新机自身版本，跨发行版运行时全部重建。
- `/srv/legacy-server/{rootfs,root-home,home,opt,boot-efi}` 保存旧机全部持久文件；活动 `/opt` 的最终同步通过排除清单保护 Ubuntu 网关、Rust `target`、Node 模块和 Python venv，再基于最终源码重新构建。
- 新旧自动出餐 worker 不得同时运行；预演期间新机通过临时 systemd drop-in 强制 `WORKER_ENABLED=false`。
- 2026-08-01 已将 `gw.hbcsch.pw` 的 TTL 600 A 记录切到新公网 IP；Cloudflare 和 Google DNS 均已返回新 IP，GA 未启用。
- DNS 缓存过渡期由旧机 Caddy 临时反代到新机，避免双机同时处理业务写入。
- 最终公开文档放入 `docs/operations/`，并更新 `docs/文档索引.md` 和 `AGENTS.md` 索引。

## 遇到的错误

- 首次远端用户列表命令中的 `awk $3` 被本地 PowerShell 展开，导致语法错误；已改用 `cut` 获取同类信息，未修改服务器。
- 旧服务器 `lsblk` 不支持 `MOUNTPOINTS` 列；磁盘容量已由 `df` 获取，后续使用兼容字段。
- 并行读取资料时，一次过宽的本地 `rg` 搜索超时；已限定目录和文件类型重查。
- 使用 root 身份读取 `csgh` 仓库 Git 状态触发 `dubious ownership`；已改为 `sudo -u csgh git -C ...`，确认仓库有 130 项未提交内容。
- 本机 `Resolve-DnsName` 受代理 Fake-IP 影响返回 `198.18.0.155`；DNS 事实采用公共 DoH/权威解析结果，当前为 `47.86.225.83`、TTL 600、无 CNAME。
- 一次远端消费者搜索范围包含历史 secret 备份，只返回了文件路径、未输出内容；后续不再搜索 `secrets/`、备份、缓存和虚拟环境。
- 本机没有可用的 `bash` 命令，首次 Bash 代码块语法检查无法运行；已把代码块通过 stdin 发送给旧服务器的 Bash 执行 `-n` 只读解析，全部通过。
- 首次 Markdown 结构检查脚本中的 PowerShell `$f:` 触发变量解析错误；已改为 `${f}` 后重跑，全部文件通过。
- 初次连接新机时，本地 VPN 出口在 SSH banner 前被服务商网络关闭；关闭 VPN后直连成功，并由旧服务器交叉确认新机 SSH 正常。
- 新机 VNC 中几条命令因 Caps Lock 变为大写而返回 `command not found`；重新以小写验证，sshd 配置有效。
- 一次新机用户列表 `awk` 受 PowerShell 转义影响；已用固定 UID/GID 的 `getent` 重查，不影响结论。
- 最终复核发现原版 `/opt rsync --delete` 会把目标机已重建运行时覆盖回旧发行版版本；已改为运行时排除清单、独立完整 `/opt` 归档和最终源码重建，并增加 dry-run 一致性验证。
- 首次活动 `/opt` checksum dry-run 因新机缺少运行时排除清单而安全退出；已按正式手册创建 root-only `runtime-rsync-excludes.txt` 后重新校验。活动 `/opt` 仅剩旧仓库 `.git` 元数据差异，完整归档 `/opt`、`/home` 均无差异。
- 首次真实生图验收使用了本机另一套 Supabase 项目配置，生产网关按预期返回 401；对比生产进程环境后确认不是新网关故障。改用新机生产环境重测，3 次真实生图全部成功并完成临时数据清理。
