# 项目安全与维护性修复实施文档

> 执行方式：按 `writing-plans` 制定步骤，使用 `test-driven-development` 补充回归验证，在当前会话分工实施并复核。用户已要求生成文档后直接执行。

**目标：** 修复 2026-09-30 分析报告指出的权限、密钥、更新、持久化和验证问题，拆分主要超大模块，保留当前工作区和生图协议。

**架构：** 继续使用 React / Tauri / Rust 网关 / Supabase / OSS。秘密只在运行环境读取；员工包不内嵌服务秘密。数据库清理由服务器时钟约束，自动安装增加 HTTPS 和 SHA-256 完整性校验。重构按业务职责提取模块，不增加外部业务服务。

**技术栈：** TypeScript、React 18、Tauri 2、Rust、Axum、PostgreSQL、Node 断言与 tsx。

## 1. 执行边界

- 基于当前未提交工作区实施，保留用户已有修改，不创建不包含现有修改的新工作树，不自动提交。
- 不读取环境文件、私密文档、SSH 密钥或 cookie 内容；安全测试只用假数据。
- 本次执行代码、迁移文件、部署模板和文档修改及本地验证。生产 SQL、网关部署、新安装包发布和更新配置写入需后续部署，不能把文件修复表述为生产已生效。
- 保留可稍后更新策略、启动检查、忙碌延后、多店铺输入和跨标签未下载图片，不恢复强制阻塞弹窗。
- 保留本地直连开发能力，改为运行时配置；正式员工包不分发本地服务秘密和认证 cookie。
- 修改后的业务模块按 JS/TS 200、Rust 250 有效行控制；对原报告严重超标模块优先拆分。配置、测试和纯类型职责分别记录统计，不用任意压缩排版规避指标。

## 3. 分阶段实施

### 任务 1：数据库历史清理

文件：`supabase/schema.sql`、新增 `supabase/migrations/20260930_harden_generation_cleanup.sql`、`src/lib/cloud-history.ts`、工作区历史调用位置、`tests/security/history-cleanup.test.ts`。

1. 写回归断言，检查普通角色执行权限被撤销、截止使用服务器时钟、前端没有全库清理 RPC。
2. 运行测试确认当前权限和 RPC 断言失败。
3. 保留旧函数签名兼容定时任务，但清理条件固定为服务器的 7 天前；撤销 PUBLIC、anon、authenticated 权限，只允许受控 service_role 和数据库计划任务。
4. 删除客户端清理调用，读取分页历史和本地过期过滤继续工作；累计计数不随历史清理减少。
5. 重跑新测试及历史相关测试；迁移文件只保存，不连接生产执行。

### 任务 2：员工包与本地秘密

文件：`src-tauri/build.rs`、`src-tauri/src/env_config.rs`、`.gitignore`、`src-tauri/tauri.conf.json`、员工构建脚本及相关文档、`tests/security/build-secrets.test.ts`。

1. 用假密钥验证构建配置不输出 `cargo:rustc-env` 密钥、不读取秘密文件；测试当前注入逻辑应失败。
2. 构建脚本仅运行 Tauri 构建准备，Rust 配置改为运行时变量 / dotenv 读取，移除 `option_env!` 服务秘密表。
3. 添加 `.env` 备份和本机 SSH 密钥忽略规则，不移动或删除原文件。
4. 删除 cookie 安装包资源声明；开发或受控本机可使用私密运行时 cookie 路径。
5. 测试通过后才运行 cargo，避免验证构建继续把本机秘密嵌入产物。

### 任务 3：更新下载完整性与兼容

文件：`src/lib/app-update.ts`、`MandatoryUpdateGate.tsx`、更新传输类型、Rust `app_update.rs` 及安全辅助模块、Cargo 依赖、`tests/mandatory-update.test.ts`、新更新安全测试。

1. 添加 HTTPS、摘要丢失 / 非法、固定 SHA-256 向量、内容变化和重定向降级测试，确认旧实现缺少保护。
2. 更新模型增加 `installer_sha256`。旧表缺列时仍可检查版本，但摘要缺失不能安装，界面明确说明并允许稍后处理。
3. Rust 只允许 HTTPS，在 `.part` 中流式下载和计算摘要，验证成功后重命名；失败清理临时文件，不启动安装。
4. 保留进度事件和安装后重新打开能力，保留忙碌延后策略。
5. 分离下载、安全校验与安装启动职责，使新增模块满足行数限制。

### 任务 4：更新配置和发布工具

文件：主 schema、新增更新迁移、`scripts/publish-app-update.mjs` 及辅助模块、`docs/自动更新.md`、更新发布离线测试。

1. 云表增加可空且格式受约束的 `installer_sha256` 与明确的发布可见性字段；对旧配置采用明确兼容规则。
2. stage 上传后同时保存 URL 和摘要，并保持未发布；enable 核验版本、HTTPS、摘要和地址后发布；disable 取消新客户端提示。旧 force_update 字段保留兼容。
3. 发布脚本可被离线测试导入，不因导入而执行网络请求；模拟上传 / 数据库响应验证配置变化。
4. 将文档描述改为可选更新，记录迁移、新老客户端兼容及发布顺序，不改写历史发布事实。
5. 不运行 publish 命令，不写生产配置。

### 任务 5：持久化状态与网关边界

文件：systemd unit、`build-and-install.sh`、`update.sh`、`bootstrap.sh`、Rust 状态路径逻辑及测试、网关跨域策略。

1. 测试模板允许状态目录写入、部署脚本创建目录。
2. 为 `/opt/csgh-gateway/state` 配置属主和权限，systemd 增加可写例外；升级脚本创建目录但不覆盖现有秘密文件。
3. 状态路径验证必须包含写入可行性；显式配置不可写时避免静默宣称持久化正常。
4. 网关来源白名单兼容 Tauri 和 Vite，允许通过公开配置扩展来源，不继续默认任意来源。
5. Rust 用临时目录测试状态保存、重载和错误，不启动实际生产网关。

### 任务 6：Rust 结构治理

文件：`backend_gateway.rs`、`video_commands.rs`、`image_proc.rs`、`prompt_templates.rs`、`gateway_queue.rs`、`gateway_limiter.rs`、共享请求类型和新增职责子模块。

1. 为源码契约测试提供限定到源码目录的模块读取助手，解析拆分后的模块，不放宽行为断言。
2. 网关入口分为鉴权、生成 / 交付、归档 / 恢复、统计 / 账号、视频解析、配置和路由组装。
3. 视频分为解析、cookie 路径、下载、导出参数、导出执行和文件历史管理；图片分为压缩、单图保存和批量调整。
4. 提示词、队列和限流器分为公共类型、核心算法、辅助逻辑和测试；共享请求定义迁至中立模块，消除对 api 入口的反向类型引用。
5. 保留 Tauri 命令名、包装宏和公开请求格式，验证库与网关二进制分别编译。
6. 每次提取先跑原有行为测试，再适配确实绑定单文件布局的旧契约测试。

### 任务 7：前端结构治理

文件：总工作区钩子、历史钩子、槽位组合钩子、图片编辑 / 批量工作区、传输入口、会话流程、管理组件、编辑公共类型。

1. 提取历史和计数状态，保留记录去重、归档失败提示、分页和 userId 变化清理。
2. 槽位组合采用无条件固定的 10 次调用，保留各店铺状态，不循环调用钩子、不按当前标签卸载工具状态。
3. 将超大图片编辑、批量任务与管理组件按实际职责拆分，不新增无用途的抽象。
4. 提取网关调用、生成、OSS 上传、文件导出、更新传输辅助模块；原 `tauri.ts` 保持兼容导出。
5. `RemotePromptConfig`、视频 CropArea / TimeRange 放到中立类型模块；Rust 类型变化同时保持前端协议。
6. 更新旧源码断言，以输入、状态、容量、跨标签保留和结果交付作为验收。

### 任务 8：统一验证与旧测试治理

文件：`package.json`、锁文件、`scripts/tests/run.mjs`、`tests/helpers/`、已有失败测试和新回归测试。

1. 锁定可用 tsx，增加 npm test 入口，逐个独立进程顺序运行测试，避免现有测试共享输出目录冲突。
2. 每个失败保留文件、退出码与原因；一次运行汇总全部结果，失败时返回非零。
3. 记录当前旧断言：UI 优先归档测试的陈旧错误文案、总工作区平台状态迁移、导航目录迁移。按当前业务行为修复测试，不恢复已移除的实现。
4. 添加真实函数 / Rust 单元行为测试，保留必要协议契约，不使用测试数量推导覆盖率。

## 5. 部署顺序与回滚

1. 备份正式数据库函数和更新表结构，通过受控 SQL 工具应用清理权限及更新配置迁移。
2. 为当前已发布安装包补充正确摘要，新包由 stage 自动写入；未补摘要的新客户端只提示，不允许自动安装。
3. 更新网关和 systemd 配置，确认状态目录写入、重启恢复与来源白名单。
4. 使用安全员工构建生成安装包，先验证下载、摘要、取消更新和安装流程，再发布可见配置。
5. 如需回滚客户端，使用旧安装包；数据库新增列保留兼容，不回滚为普通用户可全库清理的旧函数。
