# 自动更新

本文记录当前工作区的可选更新、安装包完整性校验和发布流程。2026-09-30 修复后的客户端允许“稍后更新”，仍只在启动时检查；本次代码修复不代表生产安装包、数据库或服务器已更新。

## 一、当前更新架构

安装包保存在阿里云 OSS，版本配置保存在 Supabase `public.app_update_config`，客户端通过 Rust 下载并安装，不通过网关转发安装包。

1. 启动读取更新配置；版本较新、地址非空且该版本已发布时显示提示。
2. 用户可稍后处理。检查期间或本次运行进入生图忙碌状态后，更新延后到重启，不在生成结束后补弹。
3. 缺少有效摘要、地址不是 HTTPS 或文件类型不合要求时，仍可显示版本信息，但不能自动安装，并明确显示原因。
4. 用户点击立即更新后，Rust 仅通过 HTTPS 下载；重定向也不得降级为 HTTP。
5. 下载写入临时 `.part` 文件，同时计算 SHA-256。长度和摘要校验通过、数据同步完成后，才重命名为安装包。
6. 摘要不匹配、下载失败或为空时删除临时文件，不执行安装程序。
7. 校验成功后启动 NSIS / MSI，退出旧应用并按原有流程重新打开软件。

安装包缓存使用 `updates/<版本号>/` 下的独立文件名，避免并行或上次失败下载混用。下载进度仍通过 `app-update://progress` 上报。

## 二、配置字段与兼容

| 字段 | 说明 |
|---|---|
| `id` | 固定为 `desktop` |
| `latest_version` | 最新稳定版本号 |
| `update_enabled` | 新客户端更新提示的发布开关；暂存和暂停为 false |
| `force_update` | 旧客户端兼容字段；发布工具与新开关同步维护 |
| `installer_url` | HTTPS 的 OSS 安装包地址，不写入公开文档 |
| `installer_sha256` | 对应安装包的 64 位十六进制 SHA-256 |
| `release_notes` | 每行一条更新内容 |
| `updated_at` | 更新时间 |

迁移文件是 [20260930_secure_app_updates.sql](../supabase/migrations/20260930_secure_app_updates.sql)。它为已有配置补充 `update_enabled = force_update`，允许摘要暂为空以兼容旧数据，但新客户端不会执行无摘要安装。

尚未迁移的旧表仍能被客户端读取：没有 `update_enabled` 时使用 `force_update` 判断发布可见性，没有摘要时禁止自动安装。新发布工具不会静默回退为不写摘要，必须先应用迁移。

`force_update` 不再决定新客户端是否必须安装。旧客户端是否阻塞由其旧实现决定，所以发布、暂停时应同步两个开关。

## 三、安全构建

生产员工端只需要网关地址及 Supabase 公开配置。Rust 构建不再读取本地秘密文件，不通过编译期变量内嵌生图密钥、OSS AccessKey 或 Supabase service role。

`build-employee-installer.ps1` 设置员工端网关地址后生成安装包。认证 cookie 不随安装包分发。本地直连开发、受控网关及视频解析需要的私密配置由运行时提供。

版本号仍需同时维护 `package.json`、`src-tauri/Cargo.toml`、`src-tauri/tauri.conf.json`，本次修复没有升级正式版本或上传新包。

## 四、标准发布步骤

1. 运行 `npm test` 和 `npm run build`，对 Rust 改动运行库和网关测试。
2. 通过受控数据库工具应用更新配置迁移，为需要继续提供自动安装的旧包补充真实摘要。
3. 更新版本号后先 `git commit` 并 `git push`，确保安装包对应的源码已在远端；发布脚本的 stage / upload-msi / enable 在工作区存在未提交改动时会直接拒绝。再构建员工安装包；在隔离机器验证更新取消、摘要失败和成功安装。
4. 运行 status 查看配置，再 stage 暂存新包。stage 会上传、完整下载校验，并写入 URL、摘要和更新内容，两个开关均保持 false。
5. 核对 status 的版本、对象路径和摘要，不输出完整签名 URL 或密钥。
6. enable 会再次完整下载并核验摘要，验证云端暂存版本后同时开启 `update_enabled` 和旧客户端 `force_update`。
7. 在员工机器检查启动提示、稍后更新、忙碌延后、下载失败及安装后重新打开。

命令入口如下，使用受控发布环境注入凭据：

```powershell
npm run update:publish -- status
npm run update:publish -- stage "<NSIS路径>" <版本号> <更新说明Base64>
npm run update:publish -- enable <版本号>
npm run update:publish -- disable
```

`upload-msi` 是可选人工安装包归档命令。发布脚本的 `scripts/update/` 模块可离线测试，导入模块不会自动上传或写数据库。

只有实际执行发布命令才会改变云端配置。本次修复未执行上述命令、迁移或正式安装包构建。

## 五、暂停与回滚

`disable` 同时关闭两个更新开关，后续启动的新客户端不再提示该版本。已开始安装的客户端不会被远程取消。

如需切回旧包，应写入与该包匹配的 URL、版本和 SHA-256，再验证后发布。不能只切换 URL 而保留另一个包的摘要。数据库新增字段可继续保留，旧客户端兼容字段继续维护。

SHA-256 用于检测内容与受信发布配置是否一致，不能代替代码签名。正式分发仍应按组织的 Windows 安装包签名流程执行。
