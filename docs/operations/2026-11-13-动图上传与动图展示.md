# 动图自动上传 OSS 与“动图展示”（2026-11-13）

## 需求

1. “动图制作”每生成成功一张动图（图片做动效、视频转动图都算），像图片一样自动上传 OSS 并写入云端记录；失败不影响本机使用，可手动重试。
2. 侧边栏“图片广场”下方新增“动图展示”。
3. “动图展示”只展示视频转动图的作品（所有账号、最新优先），卡片中自动播放；与图片广场一样只读、不展示链接，可放大查看。

默认处理：视频导出的 WebP 也展示（同样自动播放）；本机已有的旧动图不自动补传，记录卡片上可手动“上传到云端”。

## 数据流

```
桌面端 finish_product_animation(title) ──► 本机 result.json（含 title）
   │ 生成成功后进入后台队列（一次一个）
   ▼
read_animation_upload ──► 网关 POST /api/animation-uploads ──► OSS product-animations/<账号>/<动图ID>/result.gif|webp、poster.jpg
   │                                                       └─► 表 public.animation_uploads
   ▼
mark_animation_uploaded ──► 本机 result.json 写 uploadedAt（重启后仍显示“已上传云端”）

动图展示 ──► 网关 GET /api/animation-showcase?page=N（style=video，每页12个，最多10页，每次生成1小时签名链接）
```

## 各部分

- 数据库 `supabase/migrations/20261113_animation_uploads.sql`：新表 `animation_uploads`（动图ID主键、账号外键级联删除、风格、标题≤60字、格式 gif/webp、尺寸、2–5秒、2–100帧、≤5,000,000字节、OSS 键必须在 `product-animations/` 下）。开启 RLS，只授权 service_role 读写，客户端角色无权限。索引 `(style, created_at desc)`。
- 网关 `gateway/animation/uploads.rs`：
  - `POST /api/animation-uploads`（请求体上限 10MB）：校验登录；按文件本身判断 GIF/WebP，读取真实尺寸，用 `inspect_animation` 复核比例、分辨率、2–5秒、多帧有变化、≤5MB；封面必须是 JPEG；风格必须是已知ID。同一动图ID已由本账号上传过则直接返回成功（可安全重试），他人ID返回冲突。OSS 键由服务端生成。
  - `GET /api/animation-showcase`：只读 `style=video` 的记录，附账号显示名，动图与封面链接每次请求时签名（1小时）。
- 桌面端：`AnimationResult` 新增 `title`、`uploadedAt`（旧 result.json 兼容）；`finish_product_animation` 接收可选标题（视频名或原图文件名，去掉扩展名）；新增 `read_animation_upload`、`mark_animation_uploaded`。
- 客户端：生成成功后自动排队上传（串行）；结果预览和本机记录卡片显示“上传云端中… / 已上传云端 / 上传失败，点击重试 / 上传到云端”。“动图展示”沿用图片广场卡片与放大样式，缩略区统一 4:3 深色底完整显示；卡片进入可见范围才加载并播放动图，离开后换回封面，避免一页十几个 2–5MB 的 GIF 同时解码。

## 验证

- `npm run test:db`：完整初始化、重复初始化、增量迁移重复执行，以及重复ID、超5MB、外部OSS键被拒、客户端角色无权限、删除账号级联删除。
- 网关测试 165 项（新增：合规 GIF 通过并实测尺寸帧数时长、PNG/单帧/超时长/未知风格/非JPEG封面/超大/非法ID被拒、标题清理、分页上限）。
- 桌面端动图 Rust 测试 15 项（新增：标题清理、旧 result.json 可读）。
- 前端测试 133 项；浏览器测试：批量（4张逐个上传、带原图文件名标题、并发1）、视频（首次上传失败→重试→已上传，请求内容核对）、动图展示（鉴权、可见播放/屏幕外封面/滚动切换、卡片对齐、放大、翻页）。

## 部署顺序

1. 生产库执行迁移（只新增表）。
2. 部署网关（新增两个路由，旧客户端不受影响）。
3. 发布客户端。若客户端先于网关上线，上传会显示失败可重试、动图展示报错，不影响生成和本机保存。
