自动出餐是定时扫描 worker，**新旧实例绝对不能同时启用**。切换窗口按以下顺序执行。

### 6.1 旧机停机

```bash
ssh -i <old-server-private-key> admin@47.86.225.83
sudo systemctl disable --now chengshang-auto-meal-worker
systemctl is-active chengshang-auto-meal-worker
systemctl is-enabled chengshang-auto-meal-worker
```

预期分别为 `inactive`、`disabled`。未达到这个结果不得启动新机 worker。

### 6.2 最终状态同步

同步最新代码、平台登录状态和必要运行状态，但保留新机 Ubuntu 的 `node_modules` 与现有 `.env`。完成后再次执行 `npm ci --omit=dev`、Playwright 安装和 `npm run check`。

### 6.3 启用新机 worker

```bash
ssh -i C:/Users/Administrator/.ssh/id_ed25519 -p 22 admin@156.225.23.248

sudo rm -f /etc/systemd/system/chengshang-auto-meal-worker.service.d/00-migration-worker-disabled.conf
sudo systemctl daemon-reload
sudo systemctl enable --now chengshang-auto-meal-worker

curl -fsS http://127.0.0.1:8797/health
sudo journalctl -u chengshang-auto-meal-worker -n 200 --no-pager
```

健康结果必须为 `workerEnabled:true`。随后再次从旧机确认服务仍为 `inactive/disabled`，并观察至少一个完整扫描周期，确认没有重复任务、MongoDB 租约冲突、平台登录失效或风控提示。

## 8. 回滚

若新 worker 启用后出现阻断问题：

1. 立即在新机 `disable --now chengshang-auto-meal-worker`。
2. 确认新机服务和 8797 worker 均停止。
3. 恢复旧机最终状态并 `enable --now` 旧 worker。
4. 验证旧机 `workerEnabled:true` 后再恢复业务观察。

回滚过程中也必须始终保持只有一个 worker 执行扫描。
