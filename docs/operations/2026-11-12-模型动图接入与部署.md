# 第一种模型动图接入与部署

## 当前交付状态

模型接入代码、数据库迁移和本地验证已完成。服务器已安装FFmpeg与PostgreSQL客户端，并已构建新网关二进制；
生产数据库迁移、隔离环境全链路验证与正式切换结果将在执行后追加。未发布新安装包，Windows实机运行未验收。

第一种“热气腾腾”通过线路7的参考图异步生成接口产生真实动效，已移除该风格原来的Canvas热气替代路径。
其余五种继续本地渲染。用户确认允许模型结果等比适配输出画布并完整重复循环，原播放速度不变；
视觉与平台规则以[当前实施方案](../plans/2026-11-12-菜品动图平台导出实施.md)为准。

## 接口与数据流

| 接口 | 行为 |
|---|---|
| `GET /api/animations/capabilities` | 验证登录及账号启用状态，返回模型入口是否开放 |
| `POST /api/animations/jobs` | 接收UUID、PNG参考图Base64、输出spec，验证后创建任务，返回202 |
| `GET /api/animations/jobs` | 查询当前账号最近50条模型任务/结果 |
| `GET /api/animations/jobs?id=<UUID>` | 查询当前账号指定任务；不接受伪造user_id查他人记录 |

客户端将上传图完整等比适配到已展示的画布，PNG大小≤20MB；网关验证文件签名、真实解码、尺寸与spec一致，
仅接受`steam`、平台画布、2/3/4/5秒目标和GIF/WebP。上游要求宽高为16的倍数，不符合时客户端明确适配到默认画布。
来源使用当前上传的图片字节，绑定鉴权账号，不接受任意来源URL或本地路径。源图按内容摘要写入确定的账号/任务路径。

独立的`product_animation_jobs`表同时保存持久任务和模型动图记录；普通账号无直接表/RPC权限，全部经网关鉴权访问。
旧客户端继续读取原来的`generation_logs`，不会收到未知GIF分类；本次不修改旧统计，也不把动图压成JPEG写入旧历史。
用户可在新客户端“模型动图·云端任务与记录”中跨电脑查询并保存；本机历史保留下载后的文件。

OSS路径仅由服务器按账号UUID与任务UUID生成，保存`source-<摘要>.png`、`original.gif`、`result.gif`或`result.webp`、`poster.jpg`。
任务表存对象key、媒体信息和摘要，不持久存签名URL或真实密钥。查询时签发1小时有效结果URL。
导出件下载到桌面后再次校验SHA-256、真实格式、帧数、尺寸、时长及5M限制，再写入本机记录；以后下载仍复检。

## 提交、并发与恢复

- 浏览器在发起请求前保存请求UUID和参数/图片摘要；网络失败后只允许同图同参数使用同一UUID重试。刷新只查询，不新建付费任务。
- 数据库事务锁与唯一约束保证同一UUID去重、同账号最多一个未结束任务、最多20个未结束任务。
- 两个worker通过数据库租约原子领取，每次同时最多2个模型任务进入运行状态；未知接单状态也占用该模型并发预算。
- 正常执行时持有既有线路7/账号/全局队列许可；不自动回退到未确认支持图生GIF的其他线路。重启后重新领取已有任务及队列许可。
- 在提交前持久保存`submitting`；只有一次上游POST。收到ID后先保存再轮询，查询始终使用同一凭据摘要对应的Key。
- 提交响应不确定或提交后写ID失败时进入`reconciling`，不会自动重新提交。有上游ID的任务可继续查询；无ID的任务需要管理员核对。
- 租约10分钟；每次轮询续租，单次处理窗口约4分钟，查询/归档暂时失败后释放为15秒后可再领取，继续同一上游任务。
- 关闭`PRODUCT_ANIMATION_ENABLED`只禁止新建/领取排队任务，已提交任务继续恢复，不声称取消上游或退费。
- 更换线路Key前应排空任务；凭据摘要不一致时暂停对应查询并提示恢复原凭据，不以新Key重提。

## 原件规范化与处理预算

- 模型必须返回可解码的GIF、多于一帧、有实际画面变化；PNG、单帧、损坏或静态重复帧直接失败。
- 原件最多32MiB、单帧不超过2048×1536、最多100帧、累计解码不超过6400万像素；导出累计帧画布同样限制6400万像素。
- 等比缩放、补深色边，选择最接近目标且总长2–5秒的完整循环次数。不裁切、不拉伸，不生成虚构热气或中间帧。
- GIF优先256/128/64色；WebP优先82/65/45质量，最多三次编码，不偷偷降低所选输出尺寸。
- FFmpeg每次最多120秒；临时输出最多64MiB，结束后删除临时目录。4.x使用`-vsync 0`，新版本使用`-fps_mode passthrough`。
- WebP仅对末帧≤20ms的编码舍入做修正；不能借此改变非均匀帧的原始播放节奏。
- 成品必须为精确4:3或16:9、达到用户规定分辨率、2–5秒、有动态且≤5,000,000字节；不合规时不交付，不自动重新生成。
- 页面展示模型原始分辨率/时长、是否放大、完整循环次数和实际成品参数。放大无法恢复原件丢失的细节。

## 部署顺序与回滚

1. 运行`supabase/migrations/20261112_product_animation_jobs.sql`。只新增独立表、索引及受限RPC，不改旧历史；事务执行后通知PostgREST刷新schema。
2. 安装支持GIF、libwebp_anim的FFmpeg。网关配置`PRODUCT_ANIMATION_ENABLED=true`可开放新任务；默认关闭。
   `PRODUCT_ANIMATION_FFMPEG`可指定绝对路径，缺省`ffmpeg`。沿用线路7、Supabase service-role及OSS现有受控环境注入，禁止把值写入客户端或文档。
3. 用`--no-default-features --features gateway --bin backend-gateway`构建；隔离验证实例必须使用独立`GATEWAY_STATE_DIR`和监听端口，避免恢复生产APIMart任务。
4. 先完成真实模型→任务→OSS→导出→云端查询测试，再在静态请求排空后切换正式二进制；保存旧二进制便于回滚。
5. 新客户端需另按[自动更新](../自动更新.md)打包发布；本轮提交/网关上线不代表员工端已自动更新。

回滚优先关闭新建开关，保持任务恢复和结果查询。数据库表、原件和已成功记录不删除；不得将未确认的提交简单改回queued。
如果必须回滚二进制，先停用入口并处理/记录在途任务；旧二进制不理解模型动图路由，客户端会明确提示服务不可用。

## 已知边界

- 模型是否保持原图文字与构图不具备可靠自动判断；预览供用户确认，不声称模型输出必然保真。
- 原件低分辨率是上游实际限制；本轮采用用户明确选择的放大/完整循环策略。
- 云端返回最近50条但暂未执行7天自动清理；不会随旧历史cron误删。任务去重标识应长期保留；OSS生命周期与源图/失败上传孤立对象清理需单独配置，不能直接删除在途输入。
- 未接入旧成功作品总数和图片广场，避免静态链路混入GIF；模型记录在动图工作区独立展示。
- Windows WebView播放、中文路径保存与覆盖安装需实机验收；Mac与Linux成功不替代Windows验证。
