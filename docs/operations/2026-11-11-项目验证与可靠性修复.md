## 历史归档幂等

- 新增迁移 `20261111_generation_archive_idempotency.sql`。在写入历史前，按账号、图片类型和去掉签名参数的 OSS URL 摘要登记唯一凭据；重复 INSERT 成功返回但不新增明细，不触发累计递增。
- 迁移保留已有明细和统计，仅回填凭据，不自动删除历史重复记录或扣减旧统计。迁移短暂锁住历史表写入，部署时应安排合适窗口。
- 幂等凭据不随七天历史清理删除，防止旧任务再次累计；只存摘要和标识，不存签名 URL，需随业务规模监测该表容量。
- APIMart 待恢复任务保存已归档的 URL 和对象 key。数据库写入失败后恢复时复用原图，不再次生成或上传新的 OSS 对象。
- 此机制保证同一归档对象不会重复累计，不把用户可自行写入的历史变成计费可信事件。独立的两次生图仍是两个对象、分别计数。
- PostgreSQL 已验证重复签名、不同账号、历史清理后重试、迁移重跑和双连接并发写入；旧历史重复数据保持原样。
- 部署顺序：先应用数据库迁移，再部署网关；无需更新客户端。回滚时可停用 `before_generation_log_claim_archive` 触发器，保留凭据表与既有记录。

## 图片下载边界

参考图下载和上游结果下载共用安全下载器：只接受公共 HTTP/HTTPS 标准端口，拒绝 URL 凭据、
本机、私网、链路本地、保留地址及其 IPv6/数字变体。每一跳重定向都重新校验并解析 DNS，
拒绝混合公私网解析结果，并把通过检查的地址固定到实际连接，避免二次 DNS 解析绕过检查。
下载器不使用环境代理，不允许 HTTPS 降级，最多五次重定向，响应头和流式读取都执行 32 MiB 上限。

为兼容上游 CDN，默认允许满足上述条件的公共域名，不硬编码供应商域名列表；私有 OSS 内网端点不支持此下载链路。
参考图诊断只记录地址摘要，不再额外请求用户提供的 URL。下载错误不带完整 URL 或签名参数。
IPv4/IPv6、混合 DNS、重定向、流式超限及拒绝内网的离线测试均纳入 Rust 测试。
