## 历史归档幂等

- 新增迁移 `20261111_generation_archive_idempotency.sql`。在写入历史前，按账号、图片类型和去掉签名参数的 OSS URL 摘要登记唯一凭据；重复 INSERT 成功返回但不新增明细，不触发累计递增。
- 迁移保留已有明细和统计，仅回填凭据，不自动删除历史重复记录或扣减旧统计。迁移短暂锁住历史表写入，部署时应安排合适窗口。
- 幂等凭据不随七天历史清理删除，防止旧任务再次累计；只存摘要和标识，不存签名 URL，需随业务规模监测该表容量。
- APIMart 待恢复任务保存已归档的 URL 和对象 key。数据库写入失败后恢复时复用原图，不再次生成或上传新的 OSS 对象。
- 此机制保证同一归档对象不会重复累计，不把用户可自行写入的历史变成计费可信事件。独立的两次生图仍是两个对象、分别计数。
- PostgreSQL 已验证重复签名、不同账号、历史清理后重试、迁移重跑和双连接并发写入；旧历史重复数据保持原样。
- 部署顺序：先应用数据库迁移，再部署网关；无需更新客户端。回滚时可停用 `before_generation_log_claim_archive` 触发器，保留凭据表与既有记录。

## 图片下载边界

参考图下载和上游结果下载共用安全下载器：只接受公共 HTTP/HTTPS 标准端口，拒绝 URL 凭据、
本机、私网、链路本地、保留地址及其 IPv6/数字变体。每一跳重定向都重新校验并解析 DNS，
拒绝混合公私网解析结果，并把通过检查的地址固定到实际连接，避免二次 DNS 解析绕过检查。
下载器不使用环境代理，不允许 HTTPS 降级，最多五次重定向，响应头和流式读取都执行 32 MiB 上限。

为兼容上游 CDN，默认允许满足上述条件的公共域名，不硬编码供应商域名列表；私有 OSS 内网端点不支持此下载链路。
参考图诊断只记录地址摘要，不再额外请求用户提供的 URL。下载错误不带完整 URL 或签名参数。
IPv4/IPv6、混合 DNS、重定向、流式超限及拒绝内网的离线测试均纳入 Rust 测试。

## 排队、断线和任务恢复

- 等待队列默认最多 100 项（`GATEWAY_GENERATION_MAX_WAITING`），单账号等待数量最多为其执行并发的两倍。
- 排队默认最多 120 秒（`GATEWAY_GENERATION_QUEUE_TIMEOUT_SECS`）；超时移除票据并说明尚未提交上游，不消耗上游调用。
- 通过鉴权的生图工作在独立任务中完成，HTTP 连接断开不会取消已开始的生图及归档；客户端等待超时时提示先检查历史，避免盲目重提。
- APIMart 正常处理与恢复任务互斥。持久化先写临时文件并同步，再原子替换；写盘失败不发布内存状态，损坏文件会阻止网关启动，避免静默丢失待恢复任务。
- 只有明确的 APIMart 任务失败或任务接口 404 才移除恢复记录。轮询网络错误、OSS 404 和数据库 404 均保留任务。
- 上游已经返回任务编号或图片后，保存恢复记录、轮询、下载的失败不会触发重新提交生图。
- 这不承诺所有任务在客户端十分钟等待内完成。网关进程重启仍只能恢复有持久任务编号的 APIMart 请求；其他线路发布时应先停止新请求并等待在途任务归档。

使用独立 Chrome 无头进程加载真实 `useGenerationWorkspace` 和全部 101 个常驻工具槽位。
关闭环境文件读取并阻断非本机请求，不登录、不调用上游，不使用真实图片；向十个全店图槽位分别装入
1、10、20 张各 512 KiB 的独立随机图片载荷，按当前 `UploadedImage` 格式保留 Base64 和 Data URL。
每轮执行两帧更新和 Chrome 垃圾回收，再读取 CDP `Runtime.getHeapUsage`。

|---|---:|---:|---:|
| 空工作区 | 0 | 3.98 MiB | 2.83 MiB |
| 十槽位各一张 | 10 | 4.01 MiB | 9.50 MiB |
| 十槽位各十张 | 100 | 4.11 MiB | 69.50 MiB |

测量中无页面异常和外部请求。图片存储增量约为输入字节的 4/3，符合 Base64 体积；未发现这组操作中的
跨重置图片缓存残留。暂不更改会话状态架构或清除用户尚未下载的结果。
这些结果只覆盖 Chrome 下的工作区输入缓存，不等于 Windows WebView 的进程内存、预览解码/GPU 内存、
所有生成结果或长时间真实使用的内存保证。
