### 3.1 公网 IP 或 VPN 变化后无法连接

如果 SSH 因本机公网 IP、运营商线路或 VPN 出口变化而超时，应保持 VNC 控制台打开。VNC 不一定能正确粘贴多行脚本，因此下面每个代码框都只有一条命令：必须按顺序逐条复制、粘贴并按回车，不要一次复制多个代码框。

第一步，确认 `admin` 公钥存在：

```bash
sudo test -s /home/admin/.ssh/authorized_keys && echo ADMIN_KEY_OK || echo ADMIN_KEY_MISSING
```

必须看到 `ADMIN_KEY_OK`。如果显示 `ADMIN_KEY_MISSING`，立即停止，不要执行后面的命令。

第二步，修正公钥目录权限：

```bash
sudo chown -R admin:admin /home/admin/.ssh && sudo chmod 700 /home/admin/.ssh && sudo chmod 600 /home/admin/.ssh/authorized_keys && echo ADMIN_KEY_PERMISSIONS_OK
```

第三步，写入只允许私钥登录的 SSH 配置。下面虽然可能在文档中自动换行显示，但它是一条完整命令，只复制这一个代码框：

```bash
printf '%s\n' 'PubkeyAuthentication yes' 'PasswordAuthentication no' 'KbdInteractiveAuthentication no' 'PermitRootLogin no' 'MaxAuthTries 3' 'LoginGraceTime 30' 'MaxStartups 30:30:100' 'TCPKeepAlive yes' 'ClientAliveInterval 60' 'ClientAliveCountMax 3' 'UseDNS no' | sudo tee /etc/ssh/sshd_config.d/00-csgh-key-only.conf >/dev/null
```

第四步，在重启前验证配置语法：

```bash
sudo sshd -t && echo SSH_CONFIG_OK
```

必须看到 `SSH_CONFIG_OK`。如果出现错误，立即停止并保持 VNC 打开。

第五步，允许任意公网 IP 或 VPN 出口访问 22 端口：

```bash
sudo ufw allow 22/tcp comment 'SSH key-only access' && sudo ufw reload && echo UFW_SSH_OK
```

第六步，启用并重启 SSH：

```bash
sudo systemctl enable ssh && sudo systemctl restart ssh && sudo systemctl is-active ssh
```

最后一行必须显示 `active`。然后执行最终检查：

```bash
sudo sshd -T | grep -E '^(pubkeyauthentication|passwordauthentication|kbdinteractiveauthentication|permitrootlogin|maxstartups|clientaliveinterval|clientalivecountmax)'
```

该配置允许任意公网 IP 或 VPN 出口访问 22 端口，但关闭 SSH 密码登录和 root 登录，只允许已写入 `/home/admin/.ssh/authorized_keys` 的私钥。全部完成后，先从另一终端建立新的 SSH 会话并验证成功，再关闭 VNC。
